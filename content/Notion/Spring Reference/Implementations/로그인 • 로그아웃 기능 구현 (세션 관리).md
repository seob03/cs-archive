```java
@Data
public class LoginForm {
    @NotEmpty
    private String loginId;
    @NotEmpty
    private String password;
}
```

```java
@PostMapping("/login")
public String login(@Valid @ModelAttribute LoginForm form, 
											BindingResult bindingResult,
                      @RequestParam(defaultValue = "/")String redirectURL,
                      HttpServletRequest request) {
                      
    if (bindingResult.hasErrors()) {
        return "login/loginForm";
    }
    
    Member loginMember = loginService.login(form.getLoginId(), form.getPassword());

    if (loginMember == null) {
        bindingResult.reject("loginFail", "아이디 또는 비밀번호가 맞지 않습니다.");
        return "login/loginForm";
    }

    // 세션이 있으면 있는 세션을 반환, 없으면 신규 세션을 생성 (true)
    HttpSession session = request.getSession(true);
    // 세션에 로그인 회원 정보 보관
    session.setAttribute("loginMember", loginMember);

    return "redirect:" + redirectURL;
}
```

- 로그인 요청이 오면 ID와 PW가 자동으로 모델 객체에 바인딩 된다.
- 만약 유효성 검사를 해서 오류가 발생하는 경우에는 `BindingResult`에 저장이 된다.
	- `@ModelAttribute`에서 자동 타입 검증 + `@Valid`에서 검증이 수행된다.
- 오류가 없는 경우에는 입력한 ID, PW를 기반으로 로그인을 수행한다.
	- 만약 로그인한 유저가 아닌 경우(오류 발생)에는 `BindingResult`에 오류를 담는다.
- 해당 유저의 기존 세션을 가져오고, 만약 없으면 세션을 새로 생성한다.
	- `session`에 조회를 했을 뿐, 아직 서버 세션 저장소에 보관한 것은 아니다.
- `session.setAttribute(key, value)`를 통해 해당 유저의 세션 정보를 보관한다.
	- 세션 정보를 보관해야 이후에 `@SessionAttribute`로 인증이 가능해 진다.
	- 참고로 `“loginMember”` 문자열이 key, `loginMember` 객체가 value다. ⭐
	- 그래서 `@SessionAttribute`에서 조회할 때 key 값인 문자열 `“loginMember”`이 필요하다.
	- 만약 해당 세션이 존재하면 value인 `loginMember` 객체를 반환한다. ⭐

```java
@PostMapping("/logout")
public String logout(HttpServletRequest request) {
    HttpSession session = request.getSession(false);
    if (session != null) {
        session.invalidate();
    }
    return "redirect:/";
}
```

- 로그아웃의 경우에는 요청에 담긴 세션을 가져오고
	- 참고로 이때는 세션 없다고 해서 새로 생성하지 X
- 그 세션이 존재하는 경우에는 제거한다.
